# Шаблон Бази Знань Проєкту (Knowledge Base Starter Kit)

Універсальний стартовий набір скілів та структури бази знань для організації повного циклу управління вимогами, архітектурними рішеннями, аналітикою та задачами тестування й розробки за допомогою AI-агентів.

Центральна база знань проєкту підключена через **Notion MCP** у вашому воркспейсі Notion на сторінці **[База знань проєкту](https://app.notion.com/p/4018b55f9a7e809a87c5e83a8185bd10)**.

## 📋 Структура бази даних «1. Нормалізовані вимоги»

| Колонка | Тип у Notion | Опис / Значення |
|---|---|---|
| **ID нормалізованої вимоги** | Auto Increment ID | Префікс `REQ-` (наприклад, `REQ-1`) |
| **Назва** | Title | Коротка назва вимоги |
| **Нормалізована вимога** | Text | Чітке атомарне формулювання вимоги |
| **Тип** | Select | `Функціональна`, `Нефункціональна`, `Бізнес-вимога`, `Технічна`, `Інтеграційна` |
| **Джерело** | Text | Посилання на ТЗ, User Story, баг, тікет Jira чи документ Confluence |
| **Нормалізація** | Text | Опис декомпозиції або пояснення змін |
| **Стан** | Status | `потребує аналізу` *(за замовчуванням)*, `в процесі аналізу`, `узгоджено`, `відхилено` |
| **Ким підтверджено** | Text | Заповнюється **виключно для підтверджених/узгоджених вимог** (зі станом `узгоджено`). Вказується ПІБ/роль стейкхолдера. Для решти станів — залишається порожнім (`null`). |

Головний оркестратор наповнення всієї бази знань: [`knowledge-base-manager`](file:///.agents/skills/knowledge-base-manager/SKILL.md).

### Можливості майстер-скіла:
1. **Маршрутизація артефактів**: аналізує будь-які вхідні матеріали та розподіляє їх між 5 розділами бази знань.
2. **Делегування спеціалізованим скілам**:
   - Розділ 1 («Нормалізовані вимоги») -> [`requirements-normalizer`](file:///.agents/skills/requirements-normalizer/SKILL.md) та [`requirements-decision-applier`](file:///.agents/skills/requirements-decision-applier/SKILL.md)
   - Розділ 2 («Проміжні результати аналізу вимог») -> [`requirements-analyzer`](file:///.agents/skills/requirements-analyzer/SKILL.md), [`requirements-resolver`](file:///.agents/skills/requirements-resolver/SKILL.md) та [`requirements-decision-applier`](file:///.agents/skills/requirements-decision-applier/SKILL.md)
   - Розділ 3 («Зафіксовані прийняті рішення») -> [`requirements-resolver`](file:///.agents/skills/requirements-resolver/SKILL.md) (ADR Log)
   - Розділ 5 («Схема АПІ») -> [`openapi-spec-generator`](file:///.agents/skills/openapi-spec-generator/SKILL.md)
   - Розділ 4 («Сформовані задачі») -> спеціалізований підпроцес задач тестування (*Task Breakdown*).
3. **Обов'язкові уточнення (Ask Clarifications Rule)**: якщо у вхідних даних бракує інформації, є суперечності чи сумніви — агент обов'язково зупиняється та задає уточнюючі питання користувачеві перед внесенням змін.

## 🧠 Скіл нормалізації вимог: `requirements-normalizer`

У проєкті налаштовано спеціалізований скіл: [`requirements-normalizer`](file:///.agents/skills/requirements-normalizer/SKILL.md) (також доступний глобально в Antigravity).

### Основні принципи:
1. **Незмінність суті**: скіл тільки декомпозує вимоги до атомарного стану, суворо зберігаючи бізнес-логіку, граничні значення, умови та обмеження джерела (без додумування "від себе").
2. **Підтримка джерел**: `.md`, Word (`.docx`), Google Docs, Excel (`.xlsx`, `.csv`), Google Sheets, експорт або API з **Jira** (тікети, епіки) та **Confluence** (PRD, SRS), текстовий діалог у чаті.
3. **Автоматичний експорт**: усі атомарні вимоги публікуються в базу Notion «1. Нормалізовані вимоги» зі станом **`потребує аналізу`** українською мовою.

## 🔬 Скіл аналізу вимог: `requirements-analyzer`

Спеціалізований скіл для аналізу та валідації якості вимог: [`requirements-analyzer`](file:///.agents/skills/requirements-analyzer/SKILL.md) (також доступний глобально в Antigravity).

### Основні принципи та логіка:
1. **Фільтрація вимог**: аналізує вимоги з реєстру «1. Нормалізовані вимоги», стан яких ще не підтверджено (відмінний від `узгоджено`).
2. **Якщо проблем НЕ виявлено**:
   - Переводить стан вимоги в **`узгоджено`**.
   - У колонку **`Ким підтверджено`** записує ім'я агента: `AI Agent (Requirements Analyzer)`.
3. **Якщо виявлено проблеми/прогалини**:
   - Переводить стан вимоги в **`в процесі аналізу`**.
   - Поле `Ким підтверджено` залишається порожнім (`null`).
   - Додає запис у таблицю розділу **«2. Проміжні результати аналізу вимог»** з `ID` вимоги, виявленим дефектом, відкритими питаннями до стейкхолдерів та варіантами вирішення.
4. **⛔ Заборона самовільних рішень**: агент ніколи не приймає бізнес-рішення самостійно, лише формулює варіанти та запитання.

## 📝 Скіл вирішення проблемних вимог: `requirements-resolver`

Спеціалізований скіл для формування анкет та синхронізації відповідей стейкхолдерів: [`requirements-resolver`](file:///.agents/skills/requirements-resolver/SKILL.md) (також доступний глобально в Antigravity).

### Основні принципи та робочий процес:
1. **Генерація опитувальних .md анкет**: зчитує проблемні вимоги з Notion та формує файл з чіткими виділеними полями для вводу людиною (`Рішення / Точні вимоги`, `Ким підтверджено`, `Дата`, `Статус`).
2. **Збереження поза Git (Безпека)**: анкети зберігаються виключно в ізольованій папці `clarifications/` (внесена до `.gitignore`), що гарантує відсутність потрапляння внутрішніх чернеток і приватних відповідей у репозиторій.
3. **Автоматична синхронізація рішень з Notion**:
   - Оновлює стан узгоджених вимог у базі «1. Нормалізовані вимоги» на `узгоджено` та заповнює колонку `Ким підтверджено` ПІБ стейкхолдера.
   - Фіксує прийняті людиною правила як архітектурні рішення (ADR) на сторінці **[3. Зафіксовані прийняті рішення](https://app.notion.com/p/4018b55f9a7e811a960ecaf7e93058a2)**.
   - Оновлює реєстр проблем у **[2. Проміжні результати аналізу вимог](https://app.notion.com/p/4018b55f9a7e81c8ad3ed8f74be12f55)**, маркуючи їх як вирішені.
4. **🚫 Правило фільтрації (виключення з файлу аналізу)**: якщо в блоці аналізу вимог (Розділ 2) вимога вже має статус **`взята в роботу`** або **`вирішена`**, вона **НЕ потрапляє** у файл аналізу (`clarifications/*.md`).

## ⚖️ Скіл застосування рішень: `requirements-decision-applier`

Спеціалізований скіл для аналізу відповідей у Markdown-анкетах та оновлення статусів у Notion: [`requirements-decision-applier`](file:///.agents/skills/requirements-decision-applier/SKILL.md) (також доступний глобально в Antigravity).

### Основні принципи та логіка:
1. **Аналіз відповідей у .md файлах**: зчитує заповнені людиною анкети з `clarifications/` та валідує, чи усуває запропоноване рішення виявлену проблему.
2. **Оновлення в «1. Нормалізовані вимоги»**:
   - Змінює стан вимоги на **`узгоджено`**.
   - У колонку **`Ким підтверджено`** вписує назву агента: `AI Agent (Requirements Decision Applier)`.
   - Оновлює текст нормалізованої вимоги з урахуванням затвердженого правила.
3. **Оновлення в «2. Проміжні результати аналізу вимог»**:
   - Встановлює біля відповідної вимоги в таблиці дефектів чітку позначку **`✅ Вирішено`**.

## 🔌 Скіл генерації специфікацій API: `openapi-spec-generator`

Спеціалізований скіл для створення та підтримки актуальних API-специфікацій: [`openapi-spec-generator`](file:///.agents/skills/openapi-spec-generator/SKILL.md) (також доступний глобально в Antigravity).

### Основні принципи та можливості:
1. **Генерація OpenAPI 3.0+**: приймає на вхід посилання на Swagger UI, сирі JSON/YAML схеми, описи або код контролерів і структурує їх за стандартом OpenAPI 3.0+.
2. **Збереження в Notion**: автоматично публікує сформовану документацію на сторінці **[5. Схема АПІ](https://app.notion.com/p/4018b55f9a7e8182bcf2f14567c2c329)**.
3. **Повний комплект артефактів**:
   - Оглядова матриця всіх ендпоінтів у таблиці (Метод, Шлях, Тег, Опис, Авторизація, Відповіді).
   - Детальний розбір DTO моделей запитів/відповідей та обов'язкових статус-кодів (2xx, 4xx, 5xx).
   - Повний машинно-читабельний блок OpenAPI (YAML/JSON) для імпорту в Postman або генератори автотестів.
