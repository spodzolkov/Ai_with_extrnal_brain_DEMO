# Requirements Decision Applier (Аналізатор та Застосовувач Рішень щодо Вимог)

Цей скіл автоматизує фінальний крок циклу уточнення вимог: він зчитує заповнений людиною Markdown-файл анкети (з папки `clarifications/`), аналізує надані відповіді на предмет повноти та усунення дефекту, і якщо рішення дійсно вирішує проблему:
1. **У базі Notion «1. Нормалізовані вимоги»**:
   - Переводить стан вимоги у **`узгоджено`**.
   - У колонку **`Ким підтверджено`** вписує назву агента: **`AI Agent (Requirements Decision Applier)`**.
   - Оновлює текст нормалізованої вимоги згідно з прийнятим рішенням.
2. **У розділі «2. Проміжні результати аналізу вимог»**:
   - Біля відповідної вимоги в таблиці дефектів додає позначку: **`✅ Вирішено`**.

Усі операції, коментарі, логи та діалоги ведуться **виключно українською мовою**.

## 🔍 Критерії Валідації Відповіді Людини

Перед внесенням змін у Notion скіл перевіряє заповнені поля:
1. **Наявність відповіді**: поле `Рішення / Точні вимоги` не повинно бути порожнім, містити плейсхолдери або формальні відписки («не знаю», «пізніше»).
2. **Усунення первинного дефекту**: надане рішення повинно безпосередньо закривати виявлену проблему (наприклад, якщо бракувало граничних значень довжини — у відповіді мають бути чіткі числа/формат).
3. **Однозначність**: відповідь не повинна породжувати нових суперечностей або суб'єктивних трактувань.

## 🛠️ Детальні Інструкції з Оновлення Notion через MCP

### Крок 1. Зчитування та парсинг файлу
- Знайти вказаний файл у папці `clarifications/` (наприклад, `clarifications/clarification_20261022.md`).
- Зчитати вміст через `view_file`.
- Виділити для кожної вимоги:
  * `ID вимоги` (наприклад, `REQ-1`).
  * `Назва вимоги`.
  * `Виявлена проблема / дефект`.
  * `Обраний варіант / Рішення людини`.
  * `Ким підтверджено зі сторони стейкхолдера` (ПІБ та роль).

---

### Крок 2. Оновлення бази «1. Нормалізовані вимоги»
Для кожної вирішеної вимоги викликати `notion-update-page`:
- **Пошук картки**: через `notion-query-data-sources` за ID вимоги в `collection://7882d176-0f8f-4c66-b396-604989a9ea81`.
- **Властивості для оновлення:**
  * **`Стан`**: `узгоджено`
  * **`Ким підтверджено`**: `AI Agent (Requirements Decision Applier)`
  * **`Нормалізована вимога`**: оновлене формулювання вимоги, збагачене прийнятим людиною рішенням (наприклад: додано точні ліміти, формати, правила).
  * **`Нормалізація`**: помітка про джерело рішення (наприклад: *«Дефект довжини пароля усунено згідно з рішенням Олени Коваль від 22.10.2026. Затверджено агентом.»*).

---

### Крок 3. Оновлення сторінки «2. Проміжні результати аналізу вимог»
На сторінці `4018b55f-9a7e-81c8-ad3e-d8f74be12f55`:
- Знайти в таблиці проблемних вимог рядок із відповідним `ID вимоги`.
- Оновити статус запису, додавши чітку позначку: **`✅ Вирішено`** (або замінити вміст колонки статусу / рішення на: `✅ Вирішено (Затверджено: AI Agent (Requirements Decision Applier))`).

#### Приклад оновленої таблиці в Розділі 2:
| ID вимоги | Назва вимоги | Виявлена проблема / Дефект | Рішення / Статус |
|---|---|---|---|
| **REQ-1** | [Реєстрація користувача](...) | Відсутні граничні значення для довжини пароля | **✅ Вирішено** (Довжина 8..64, 1 велика літера, 1 цифра, 1 спецсимвол) |
| **REQ-2** | [Пошук товарів](...) | Не визначено алгоритм сортування за замовчуванням | **В процесі аналізу** (Очікується відповідь PO) |

## 📊 Крок 4. Звіт Користувачеві

Після завершення синхронізації агент надає короткий структурований звіт:
1. **Опрацьований файл**: посилання на локальний файл у `clarifications/`.
2. **Кількість опрацьованих вимог**: скільки переведено в `узгоджено`, скільки залишилося без змін (і чому).
3. **Оновлені записи в Notion**: клікабельні посилання на оновлені картки вимог та сторінку проміжного аналізу.
